# 监听器使用教程

本文以 Minecraft 26.2、Luminol/Folia 26.2 build 727 为例，介绍如何安装、配置和排查“监听器（Listener）”插件。

## 1. 插件能做什么

监听器把服务器事件转换成可配置的动作。例如：

- 玩家加入时发送欢迎语、标题或音效；
- 玩家输入特定命令时执行控制台命令；
- 玩家挖掘某种方块时记录日志；
- 玩家死亡时广播消息；
- 每隔一段时间执行一次公告；
- 世界或天气变化时触发动作。

它是服务端插件，不会直接捕获客户端键盘、鼠标、屏幕渲染或客户端音乐等 FancyMenu Mixin 事件。

## 2. 安装

### 2.1 使用已构建的 JAR

1. 下载仓库构建产物 `Listener-1.0.0.jar`。
2. 将 JAR 放到服务器根目录的 `plugins` 文件夹。
3. 完整重启服务器，不建议在生产服使用其他插件的热加载器加载它。
4. 首次启动后，插件会生成：

   ```text
   plugins/Listener/config.yml
   ```

### 2.2 从源码构建

在项目根目录执行：

```powershell
gradle clean build
```

构建产物位于：

```text
build/libs/Listener-1.0.0.jar
```

插件面向 Java 25 和 Folia 调度器，`PlaceholderAPI` 是可选依赖，不安装也可以使用内置变量。

## 3. 第一个规则：玩家加入时发送消息

打开 `plugins/Listener/config.yml`，在 `listeners:` 下加入：

```yaml
listeners:
  welcome:
    event: player_join
    enabled: true
    actions:
      - type: message
        value: "&a欢迎来到服务器，%player_name%！"
```

保存后，在游戏或控制台执行：

```text
/listener reload
```

下一名玩家加入时，就会收到绿色欢迎消息。`&a` 是 Bukkit 的颜色代码，`%player_name%` 会替换成玩家名称。

## 4. 配置结构

每个监听器规则由一个唯一 ID 作为键：

```yaml
listeners:
  规则id:
    event: 事件名
    enabled: true
    filters:
      字段: 匹配值
    interval_ticks: 1200
    actions:
      - type: 动作类型
        value: 动作参数
        delay_ticks: 0
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `event` | 是 | 要监听的事件名称，例如 `player_join`、`block_break`。 |
| `enabled` | 否 | 是否启用，默认为 `true`。 |
| `filters` | 否 | 事件过滤器，所有过滤器都满足时才执行动作。 |
| `actions` | 是 | 按顺序定义一个或多个动作。 |
| `delay_ticks` | 否 | 单个动作延迟的 tick 数，20 tick 约等于 1 秒。 |
| `interval_ticks` | timer 必填 | `timer` 规则的执行间隔，默认为 20 tick。 |

规则 ID 建议使用英文、数字、短横线或下划线，例如 `welcome`、`night-announcement`。同一个 ID 只能定义一次。

## 5. 命令和权限

所有管理命令都需要 `listener.admin` 权限，默认只有 OP 拥有：

```text
/listener list
/listener info <id>
/listener gui
/listener reload
/listener test <id>
/listener fire <id>
```

命令用途：

- `list`：列出已加载的规则、事件和动作数量；
- `info <id>`：查看某条规则的过滤器、动作和定时器间隔；
- `reload`：重新读取 `config.yml`，并重建定时器；
- `test <id>` / `fire <id>`：由玩家直接执行这条规则的动作，方便测试消息、标题、音效和命令。它不需要等待对应事件发生，也不用于模拟完整事件数据。

`test` 和 `fire` 是同一个功能的两个命令名，必须由玩家执行；控制台执行时会提示需要玩家身份。

## 6. 可视化编辑器

拥有 `listener.admin` 权限（默认是 OP）的管理员可以在游戏内执行：

```text
/listener gui
```

编辑器不需要手动写 YAML，所有修改会直接保存到 `plugins/Listener/config.yml` 并自动重载：

- 规则列表中左键打开详情，右键快速启用或停用；底部可以翻页、重新加载、新建规则。
- 详情页可以测试规则、修改事件、修改首个动作，以及修改 `timer` 的执行间隔。
- 新建规则时按聊天框中的四步提示输入：规则 ID、事件名、动作类型、动作内容。输入 `cancel` 可随时取消。
- 事件和动作输入会校验支持列表；客户端 Mod 事件可以使用 `client_` 开头的事件名。

编辑器始终复用 `listener.admin` 权限。没有权限的玩家无法执行命令，也无法操作已经打开的管理界面。建议先在测试服用“立即测试”确认消息、命令或客户端动作，再让规则长期启用。

## 7. 事件列表与过滤字段

事件名必须使用下表中的值。过滤器的键来自该事件产生的字段；没有提供字段的事件不适合使用该过滤器。

| 事件 | 常用过滤字段 | 说明 |
| --- | --- | --- |
| `server_start` | `event` | 插件启用后触发一次。 |
| `timer` | `event` | 按 `interval_ticks` 周期触发。 |
| `player_join` | `player_name`、`world` | 玩家加入。 |
| `player_quit` | `player_name`、`world` | 玩家退出。 |
| `player_chat` | `player_name`、`message` | 玩家聊天，`message` 是聊天内容。 |
| `player_command` | `player_name`、`command_name`、`command` | 玩家发送命令，`command_name` 不包含开头的 `/`。 |
| `player_death` | `player_name`、`death_message` | 玩家死亡。 |
| `player_damage` | `damage_cause`、`damage` | 玩家受到伤害。 |
| `player_move` | `old_world`、`new_world` | 玩家跨方块移动时触发，不会每 tick 触发。 |
| `block_break` | `block`、`world`、`tool` | 玩家破坏方块。 |
| `block_place` | `block`、`world`、`item` | 玩家放置方块。 |
| `player_interact` | `action`、`item`、`block`、`hand` | 玩家交互。 |
| `item_consume` | `item` | 玩家食用或饮用物品。 |
| `item_pickup` | `item`、`amount` | 玩家捡起物品。 |
| `entity_spawn` | `entity`、`world`、`spawn_reason` | 实体生成，触发频率可能较高。 |
| `entity_death` | `entity`、`world`、`killer` | 实体死亡。 |
| `world_change` | `old_world`、`new_world` | 玩家切换世界。 |
| `weather_change` | `world`、`weather_type` | 下雨、雷暴或天气清除。 |
| `client_connect` | `mod_version`、`features` | 兼容客户端 Mod 握手成功。 |
| `client_*` | 由客户端 Mod 定义 | 按键、鼠标、界面、渲染、音乐等客户端事件。 |

过滤器默认是不区分大小写的精确匹配。值为空或 `*` 表示不限制；键名以 `_contains` 结尾时使用不区分大小写的包含匹配，例如：

```yaml
filters:
  message_contains: "你好"
```

## 8. 动作类型

```text
message          给当前玩家发送聊天消息
broadcast        向全服广播消息
console_command  以控制台身份执行命令
player_command   以当前玩家身份执行命令
actionbar        给当前玩家发送 Action Bar
title            给当前玩家发送标题
sound            给当前玩家播放音效
set_variable     设置插件运行时变量
log              写入插件日志
```

示例：

```yaml
actions:
  - type: message
    value: "&e这是聊天消息"
  - type: actionbar
    value: "&b这是 Action Bar"
  - type: title
    value: "&6主标题|&f副标题"
  - type: sound
    value: "minecraft:block.note_block.chime,1.0,1.0"
  - type: console_command
    value: "say %player_name% 触发了监听器"
```

`title` 的 `value` 用竖线 `|` 分隔主标题和副标题。`sound` 的格式是 `资源名,音量,音调`，建议使用完整的命名空间资源名。

## 9. 变量和 PlaceholderAPI

所有动作的 `value` 都可以使用内置变量：

```text
%player_name% %uuid% %world% %x% %y% %z%
%message% %format% %command% %command_name%
%block% %item% %entity% %damage% %raw_damage% %damage_cause%
%old_world% %new_world% %event% %listener_id%
```

变量只在当前事件有对应数据时才会有具体值；例如 `player_join` 没有 `%block%`。无法解析的占位符会原样保留，便于发现拼写错误。

部分事件还会提供更具体的变量：

```text
join_message quit_message death_message keep_inventory format
command_name raw_damage damage_cause
old_x old_y old_z new_x new_y new_z
block_x block_y block_z tool hand amount
entity_uuid spawn_reason killer weather_type
```

这些变量只能在相应事件中使用，例如 `%command_name%` 只对 `player_command` 有意义，`%spawn_reason%` 只对 `entity_spawn` 有意义。

如果服务器安装了 PlaceholderAPI，插件会通过反射继续解析 PlaceholderAPI 变量，例如：

```yaml
value: "&a%player_name% 当前延迟：%player_ping%"
```

PlaceholderAPI 不在插件 JAR 中打包，也不是硬依赖。

`set_variable` 示例：

```yaml
actions:
  - type: set_variable
    value: server_label=生存服
  - type: log
    value: "当前服务器：%server_label%"
```

运行时变量只保存在插件内存中，重启服务器后会清空；不要把它当作数据库或玩家持久化数据。

## 10. 常用配置示例

### 10.1 特定命令触发

```yaml
listeners:
  spawn_notice:
    event: player_command
    enabled: true
    filters:
      command_name: "spawn"
    actions:
      - type: actionbar
        value: "&e正在传送到出生点……"
        delay_ticks: 1
      - type: log
        value: "%player_name% 使用了 /spawn"
```

### 10.2 破坏特定方块时执行控制台命令

```yaml
listeners:
  stone_break:
    event: block_break
    enabled: true
    filters:
      block: "minecraft:stone"
    actions:
      - type: console_command
        value: "say %player_name% 挖到了石头"
```

### 10.3 定时公告

```yaml
listeners:
  heartbeat:
    event: timer
    enabled: true
    interval_ticks: 1200
    actions:
      - type: broadcast
        value: "&e服务器运行正常，祝游戏愉快！"
```

1200 tick 约等于 60 秒。Folia 环境中定时器使用全局区域调度器执行。

### 10.4 玩家死亡后延迟广播

```yaml
listeners:
  delayed_death:
    event: player_death
    enabled: true
    actions:
      - type: broadcast
        value: "&c%player_name% 已死亡。"
        delay_ticks: 20
```

## 11. 修改配置后的标准流程

每次修改 YAML 后按以下顺序操作：

1. 确认缩进使用空格，不要使用 Tab；
2. 确认 `event`、动作 `type` 拼写正确；
3. 执行 `/listener reload`；
4. 执行 `/listener list` 确认规则数量；
5. 执行 `/listener info <id>` 检查具体规则；
6. 对玩家动作使用 `/listener test <id>` 验证。

如果重载后规则数量比预期少，优先查看服务器日志中的配置警告，并检查 YAML 缩进和列表中的 `-`。

## 12. 常见问题

### 修改配置后没有效果

确认修改的是服务器实际运行目录下的 `plugins/Listener/config.yml`，然后执行 `/listener reload`。仅保存文件不会自动热重载。

### `/listener test` 提示需要玩家执行

这是设计行为：`message`、`title`、`actionbar`、`sound` 等动作需要目标玩家。请在游戏内执行，或使用 `console_command` / `log` 测试控制台动作。

### 监听器触发次数太多

`entity_spawn` 和 `item_pickup` 可能较频繁；`player_move` 已限制为跨方块触发，但仍建议使用 `filters` 缩小范围。

### 聊天事件和 Folia 线程

聊天事件可能在异步线程触发，插件会把动作交给 Folia 玩家调度器执行，不要据此在配置中假设动作立即同步完成。

### FancyMenu 的客户端监听器能否全部复刻

不能仅靠服务端 Bukkit/Folia 插件获取客户端键盘、鼠标、屏幕、渲染和客户端音乐事件。监听器现在提供可选的客户端 Mod 桥接；安装兼容 Mod 后，可以把这些事件送回服务器并由 YAML 规则处理。

## 13. 客户端 Mod 桥接

### 13.1 安装和工作方式

客户端 Mod 与服务端插件通过原生 Plugin Messaging 通道 `listener:main` 通信，不需要额外端口或 ProtocolLib。服务端没有安装客户端 Mod 时，所有原有服务端规则照常工作；客户端没有安装 Mod 时，`client_*` 动作会被安全忽略。

客户端连接后先发送 HELLO，服务端返回 HELLO_ACK。握手成功后，配套 Mod 可以发送按键、鼠标、屏幕、位置、注视目标和玩家状态事件；插件会把事件名称规范化成 `client_事件名`，字段可直接用于过滤器和变量。

### 13.2 在规则中监听客户端事件

例如客户端 Mod 上报 `keyboard_key_pressed` 并携带 `key_keycode=80`（P 键示例）：

```yaml
listeners:
  profile_key:
    event: client_keyboard_key_pressed
    filters:
      key_keycode: "80"
    actions:
      - type: client_screen
        value: "inventory"
```

客户端事件还可以触发服务端动作：

```yaml
listeners:
  client_screen_log:
    event: client_screen_open
    filters:
      screen_contains: "Screen"
    actions:
      - type: log
        value: "%player_name% 打开了客户端界面 %screen%"
```

事件字段（如 `key_keycode`、`screen`、`button`、`mouse_pos_x`）由客户端 Mod 定义；在规则中使用相同名称即可。所有客户端事件会额外带有 `source=client`，可以用它区分同名服务端字段。

### 13.3 向客户端发送动作

除了服务端已有的 `message`、`title`、`sound` 等动作，还可以使用：

```text
client_action   值格式：动作名|参数
client_message  客户端聊天/通知
client_screen   打开或关闭客户端界面
client_overlay  显示客户端覆盖层
client_sound    播放客户端资源包音效或音乐
```

示例：

```yaml
listeners:
  join_overlay:
    event: client_connect
    actions:
      - type: client_overlay
        value: "欢迎，%player_name%！"
      - type: client_sound
        value: "minecraft:ui.button.click,1.0,1.0"
```

### 13.4 协议摘要（供 Mod 开发者）

消息帧以 Java `DataOutputStream` 写入，开头固定为 `byte protocol_version=1`、`byte opcode`。字符串使用 `writeUTF/readUTF`，单字符串不超过 4096 字符，单帧不超过 32 KiB。

| 方向 | 操作码 | 内容 |
| --- | --- | --- |
| 客户端 → 服务端 | `1 HELLO` | `byte client_version`、`UTF mod_version`、`byte count`、`UTF feature` 列表 |
| 服务端 → 客户端 | `2 HELLO_ACK` | `boolean accepted`、`UTF reason`、`UTF capabilities` |
| 服务端 → 客户端 | `3 ACTION` | `UTF action`、`UTF value` |
| 客户端 → 服务端 | `4 EVENT` | `UTF event`、`byte count`、键值 `UTF key` + `UTF value` 列表 |

客户端发送不带 `client_` 前缀的事件名时，服务端会自动添加前缀。事件名和字段名只允许小写字母、数字、下划线、冒号、点和短横线。未知动作或未知字段应由客户端安全忽略，以便协议向后兼容。

安全提示：客户端上报的数据来自玩家自己的客户端，不能视为管理员签名或反作弊凭据。不要仅凭 `client_*` 事件执行踢人、封禁、权限变更等高权限控制台命令；如确需执行，请再叠加服务端权限或其他可信条件。
